---
title: "Local API authentication"
description: "How the browser UI, the MCP server and your own scripts authenticate to the local HTTP API"
---

Every `/api` route, including WebSocket and event-stream endpoints, requires a per-launch API token. Requests without a valid token receive `401 Unauthorized` with an empty body. The only exception is `GET /api/health`, which returns `{"ok":true}` and nothing else.

## Where the token lives

On every start the server generates a new random token and writes it to a file named `api-token` in its data directory, next to `profiles.json`:

| Platform | Path |
| --- | --- |
| Linux | `$XDG_DATA_HOME/vibe-kanban/api-token` (default `~/.local/share/vibe-kanban/api-token`) |
| macOS | `~/Library/Application Support/ai.bloop.vibe-kanban/api-token` |
| Development builds | `dev_assets/api-token` in the repository |

The file is readable only by the user running the server (mode `0600`, directory `0700`). The server never logs the token.

<Warning>
The token changes every time the server restarts. Read the file on each run of your script rather than copying the value somewhere else.
</Warning>

## Authenticating a script

Send the token as a bearer token:

<CodeGroup>
```bash cURL
TOKEN_FILE="${XDG_DATA_HOME:-$HOME/.local/share}/vibe-kanban/api-token"
curl -fsS -H "Authorization: Bearer $(cat "$TOKEN_FILE")" \
  http://127.0.0.1:3005/api/info
```

```python Python
import os, urllib.request

token_file = os.path.join(
    os.environ.get("XDG_DATA_HOME", os.path.expanduser("~/.local/share")),
    "vibe-kanban", "api-token",
)
token = open(token_file).read().strip()
req = urllib.request.Request(
    "http://127.0.0.1:3005/api/info",
    headers={"Authorization": f"Bearer {token}"},
)
print(urllib.request.urlopen(req).read())
```
</CodeGroup>

If a long-running script receives a `401`, re-read the token file once and retry: the server has probably restarted.

For liveness checks that do not need the token, use `GET /api/health`.

## The browser UI

When the server serves the web UI it also sets an `HttpOnly`, `SameSite=Strict` cookie holding the token, so the UI needs no extra setup. After a server restart the UI reloads itself once to pick up the new cookie.

In development (`pnpm run dev`) the Vite dev server injects the token from `dev_assets/api-token` into every proxied `/api` request.

## The MCP server

The bundled MCP server reads the token file automatically and sends it as a bearer token. On a `401` it re-reads the file once and retries, so it keeps working across server restarts. To use a token from somewhere else, set the `VK_API_TOKEN` environment variable for the MCP process.

## Allowed hosts

The server only answers requests whose `Host` header is `localhost`, `127.0.0.1` or `[::1]` (any port). Any other host receives `403 Forbidden`, which blocks DNS-rebinding attacks from web pages open in your browser.

If you reach the server through a reverse proxy under another hostname, add that origin to `VK_ALLOWED_ORIGINS` (comma-separated, for example `https://kanban.example.test`). Both the origin check and the host check use this list.
